1MySQL 服务端分层架构

常见说法是两层（Server 层 + 存储引擎层），展开是四层；右侧是一条 SQL 的实际穿行路径

1
连接层 Connection Layer
连接管理 · 线程（一连接一线程）· 认证鉴权 · MySQL 协议解析
认证 → 分配线程
权限此刻确定（改权限要重连）
2
服务层 Server Layer
解析器 → 预处理器 → 优化器 → 执行器
binlog / error log / slow log / general log · 权限、字符集、视图、存储过程、复制
SQL → 解析树 → 执行计划
→ 调用引擎接口，逐行取数
3
存储引擎层 Storage Engine 　插件式，可替换
InnoDB（默认）/ MyISAM / Memory / Archive
redo log · undo log · Buffer Pool —— 都是 InnoDB 的实现，不属于 Server 层
Buffer Pool 命中？
否则读磁盘页；update 还写 undo + redo
4
文件系统层 File System
.ibd 数据文件 · redo 日志文件 · undo 表空间 · binlog 文件 · 数据字典
真实文件 IO
O_DIRECT / fsync 等调优在这一层
这个分层直接解释了两阶段提交的根因
redo log 在 ③ 引擎层 写　·　 binlog 在 ② 服务层 写　——　 两份日志跨层、分开写，就必须保证一致，这就是为什么需要 2PC + prepare 中间态。
