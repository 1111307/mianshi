为什么这样能修碎片
老桶的分组是"历史上怎么插就怎么放"——删删插插后留下的空洞没人回收， 元素就散在多个桶里。
等量扩容不看老桶的分组，把整条链的元素收集起来按顺序紧凑重排， 等价于对索引做了一次 defragment。
顺带两个源码细节
· 等量扩容时不计算 y 目标桶——y.b 会越界， 注释写着 "Otherwise GC can see bad pointers"
· 搬迁时新挂的溢出桶不复用旧桶（源码里还是 TODO： "reuse overflow buckets instead of using new ones"）， 旧桶数组连同它末尾的预分配区整体释放
